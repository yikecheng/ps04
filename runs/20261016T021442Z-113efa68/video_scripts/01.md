## Scene 2 — Agents move beyond code generation

**Narration**

<!-- claim:01-c1 -->
Cursor says Rollouts, available on Teams and Enterprise plans, reads a diff before merge and writes a monitoring plan. A person can edit that plan. After deployment, configuration can ping the author, pause a progressive rollout, or prepare a revert pull request that waits for approval.

<!-- claim:01-c2 -->
GitHub’s generally available agentic autofix for eligible security customers explores relevant repository files, proposes a repair, reruns CodeQL, and opens a draft pull request for human review. The useful unit is not autonomous repair; it is a proposed, machine-checked change inside the existing review system.

<!-- claim:01-c3 -->
OpenAI’s code-review demonstration shows that, once a connector has the required repository permissions, an initial pull-request review can run automatically. The demonstration establishes workflow feasibility, not review accuracy.

## Scene 3 — Harnesses and controls are part of the capability

**Narration**

<!-- claim:01-c4 -->
Cursor separately reports that changes to its agent harness reduced users’ token costs by seven percent without reducing agent quality. Cursor tracked cost, latency, tool errors, and usage, but this remains an internal vendor result rather than an independent benchmark.

<!-- claim:01-c7 -->
At much larger scale, InfoQ relays GitHub’s report of an AI-assisted rewrite exceeding 800,000 production lines. It took about 14.5 weeks and 128 pull requests while releases continued. Agents produced most of the implementation, while compilation, testing, and human review exposed regressions involving behavior, state, library semantics, and lost optimizations.

Together, these reports suggest that context assembly, testing, and review infrastructure are part of the practical capability—not administrative extras.

## Scene 4 — Scale does not erase production risk

**Narration**

<!-- claim:01-c5 -->
InfoQ also reports that Spotify’s monthly merged changes grew from roughly 8,100 to 17,000 year over year in August. That is a notable throughput signal, but it is not an autonomous-correctness measure.

<!-- claim:01-c6 -->
The same Spotify account includes the counterexample: an automated dependency upgrade passed existing checks and then failed in production. Spotify subsequently strengthened safeguards, expanded rollback capacity, and scheduled automated changes during the owning teams’ working hours.

These cases are informative, not population estimates. Official releases establish availability and workflow scope, but not review accuracy, security-fix correctness, false-positive rates, latency, or return on investment. Cursor, GitHub, and OpenAI sell the featured products; their demonstrations are curated. The production cases reported by InfoQ also come from organizations far larger than a 2–20-person team.

## Scene 5 — What a small team should do now

**Narration**

For a small team, the evidence supports a measured trial. Pick one bounded workflow with an external check: a CodeQL remediation, a deterministic migration step, or an initial review pass. Require a draft pull request and named human approver. Define deployment signals before merge, stage the rollout, and test the rollback path.

Record accepted outcomes, rework, reviewer time, failures after deployment, and the cost of running the agent. Expand only if your own results improve without shifting hidden work onto reviewers or operators.

The takeaway is deliberately narrow: current agents are credible participants in controlled delivery workflows. The supplied evidence does not justify unattended deployment or the assumption that passing today’s checks means production-safe behavior.
