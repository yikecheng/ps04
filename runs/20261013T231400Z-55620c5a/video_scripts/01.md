# The Agent Moved Past the Diff, Not Past the Gate

*Estimated runtime: 4 minutes*

[VISUAL: A code diff card expands into a simple workflow: repositories → plan → isolated work → review → rollout. Put a human approval gate before merge and deployment.]

**NARRATION:** A coding agent used to be judged by the patch it produced. For a small team, the more important question now is whether the surrounding workflow is controllable: what the agent can inspect, where it can act, what evidence it returns, and where a human can stop it. That distinction separates a useful production tool from an unsupported promise of autonomous delivery.

[VISUAL: Source-title card for Sourcegraph. Animate a repository map into “Plan,” “Pilot repo,” and “Roll out.”]

<!-- claim:01-c1 -->
**NARRATION:** Sourcegraph says Agentic Batch Changes scopes a request across an indexed codebase, builds a plan, tries the change in one repository, and then rolls it out. That is broader than composing one diff, but the description is still a staged workflow.

[VISUAL: Cursor source-title card. Split screen: an editable monitoring plan on the left; a security finding with explanation and proposed fix on the right.]

<!-- claim:01-c2 -->
**NARRATION:** Cursor says Rollouts reads the diff before merge and writes a monitoring plan that a person can edit if something is missing. The useful capability here is not clairvoyance; it is an inspectable proposal before deployment.

<!-- claim:01-c3 -->
**NARRATION:** Cursor also says Security Reviewer runs on every pull request, reads the change in whole-codebase context, and reports vulnerabilities with an explanation and proposed fix. That establishes the intended scope, not its detection accuracy.

[VISUAL: Generic cloud-review diagram: repository permission → automatic review → findings card. Do not show product footage.]

<!-- claim:01-c4 -->
**NARRATION:** OpenAI says initial cloud code reviews can run automatically once its connector has repository permissions. Automatic initiation is real workflow automation; it does not, by itself, validate the review.

[VISUAL: Three parallel task lanes leading to separate worktree boxes. Label them “Project A,” “Project B,” and “Forked conversation.”]

<!-- claim:01-c5 -->
**NARRATION:** In a separate Codex CLI demonstration, OpenAI showed concurrent tasks across projects and a conversation fork isolated in a separate worktree and checkout. Isolation makes parallel execution easier to supervise.

<!-- claim:01-c8 -->
**NARRATION:** Taken together, these launches move the product surface beyond generation into review, security, repository-scale change, parallel execution, and deployment monitoring. That is a multi-source inference about workflow reach. It is not evidence that a tool can safely accept, merge, deploy, or recover without oversight.

[VISUAL: Source-title card for AgentSWE. Diagram: visible development cases → freeze delivery → hidden held-out cases.]

<!-- claim:01-c6 -->
**NARRATION:** For a counterweight, AgentSWE evaluates 25 tasks spanning creation, editing, and optimization. It freezes the delivered system, then tests it in isolation on held-out cases. That design asks whether apparent completion survives delivery.

<!-- claim:01-c7 -->
**NARRATION:** The AgentSWE authors report that Creation runs ending development at 90 or above averaged 9.9 on held-out delivery. It is a sharp gap within this benchmark, not a universal failure rate.

[VISUAL: Replace an “Autonomous delivery” stamp with a four-part control plane: Plan, Isolate, Gather evidence, Approve.]

<!-- claim:01-c9 -->
**NARRATION:** So the defensible production-ready capability is supervised orchestration, not autonomous acceptance. Sourcegraph leaves pull requests for human review and merge. Cursor describes paused rollouts or revert pull requests waiting for approval. AgentSWE warns that visible success may not survive independent acceptance. The mature layer is the control plane: planning, isolation, evidence, and explicit gates.

[VISUAL: Limitation card with three columns: “Vendor workflow descriptions,” “Missing outcome data,” and “Small specialized benchmark.”]

**NARRATION:** The evidence cannot rank these tools. Sourcegraph, Cursor, and OpenAI describe products they sell; their materials establish availability and intended workflow, not effectiveness. They provide no controlled precision, false-positive, reviewer-effort, incident-reduction, rollback-reliability, or small-team outcome data here. AgentSWE is independent, but it is a 25-task preprint focused on agent software, with uncertain representativeness and repeated-run stability.

[VISUAL: Final checklist: one bounded task; isolated workspace; CI evidence; human merge; human rollout and revert approval; measure outcomes.]

**NARRATION:** For a team of two to twenty people, start with one bounded task. Require a plan, run in an isolated branch or worktree, collect CI and review evidence, and preserve human approval for merge, rollout, and revert. Track rejected suggestions, reviewer minutes, escaped defects, and recovery results. If a feature expands what the agent can touch without improving those outcomes, it has increased reach—not demonstrated readiness.
