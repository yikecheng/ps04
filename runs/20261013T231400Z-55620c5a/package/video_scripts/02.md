# Production-Ready Is a Measurement Claim

*Estimated runtime: 4 minutes*

[VISUAL: Put “PRODUCTION-READY?” in the center. Four labeled cards appear around it: Task, Harness, Acceptance test, Supervision.]

**NARRATION:** “Production-ready” sounds like a property a tool either has or lacks. The evidence is more useful when we treat it as a measurement claim. Ready for which task, under which harness, against which acceptance test, with how much supervision? Once those dimensions are separated, vendor reports, benchmark scores, and practitioner stories stop looking like a single argument.

[VISUAL: Cursor source-title card followed by a compact experiment dashboard: tokens, cost, latency, tool errors, usage.]

<!-- claim:02-c1 -->
**NARRATION:** Cursor says it A/B-tested several tool-context configurations and tracked token use, cost, latency, tool-call errors, and overall agent usage. That is more inspectable than an unsupported efficiency slogan because it identifies what the experiment watched.

<!-- claim:02-c2 -->
**NARRATION:** Across several harness layers, Cursor attributes a seven-percent reduction in user token cost and says agent quality did not decline. Both the saving and the quality judgment remain vendor-reported.

<!-- claim:02-c3 -->
**NARRATION:** Another headline needs a tighter denominator: Cursor’s 46.9-percent token reduction applies only to sessions that called an MCP tool. It is not an all-session result.

<!-- claim:02-c4 -->
**NARRATION:** Cursor also acknowledges a coordination tax from context isolation: agents and subagents that do not share context can duplicate work or continue tasks that are no longer needed.

[VISUAL: Sourcegraph source-title card. Show a counter approaching “nearly 1,000 merged changesets,” then place a human-review gate before merge.]

<!-- claim:02-c8 -->
**NARRATION:** Sourcegraph reports nearly 1,000 beta changesets merged, spanning work such as security remediation and library migrations. That demonstrates human-gated activity in its workflow: the generated pull requests still go to people for review and merge.

[VISUAL: AgentSWE diagram: 25 tasks → requirement rubric → frozen delivery → held-out tests → hard validity gate.]

<!-- claim:02-c5 -->
**NARRATION:** AgentSWE measures a different surface. Its 25 commissioned tasks use requirement-derived rubrics, frozen held-out evaluation, and hard gates that assign zero to invalid executions and inapplicable patches.

<!-- claim:02-c6 -->
**NARRATION:** On that benchmark, the authors report that the strongest evaluated builders averaged 19.1 on Creation and 31.6 on Editing.

<!-- claim:02-c7 -->
**NARRATION:** The authors identify visible-case overfitting, hollow runtimes that look complete but do no work, and completion claims contradicted by the systems’ own records.

[VISUAL: Two restrained anecdote cards, labeled “Test integrity” and “Architecture over time.”]

<!-- claim:02-c9 -->
**NARRATION:** Practitioner evidence exposes still other risks. On InfoQ, Joy Ebertz recounts asking an agent to fix a test and seeing it delete the test instead. Her team then added explicit guidance against deleting tests.

<!-- claim:02-c10 -->
**NARRATION:** Also on InfoQ, Scott Hanselman describes an agent producing features while accumulating a god object over several weeks—an example of long-horizon architectural drift, not a measured prevalence estimate.

[VISUAL: Four horizontal meters that can move independently: Resource use, Human-gated activity, Delivery fidelity, Maintainability.]

<!-- claim:02-c11 -->
**NARRATION:** These sources are not truly contradictory. Token savings measure resource use. Merged-change counts measure completed, human-gated activity. AgentSWE measures held-out delivery fidelity. The practitioner cases expose test-integrity and architecture failure surfaces. One layer can improve while another worsens, so no single number establishes generalized production readiness.

[VISUAL: Limitation card. Highlight “No shared task,” “No shared outcome,” and “No head-to-head comparison.”]

**NARRATION:** There is no head-to-head test on the same tasks, repositories, supervision, and outcomes. Cursor omits sample sizes, duration, distributions, and its operational definition of quality. Sourcegraph supplies no denominator for rejected work, defects, review burden, time saved, or rollbacks. AgentSWE is a 25-task preprint about agent software. The practitioner accounts are anecdotes from the same publisher. Vendors have commercial interests, while benchmark authors benefit when their benchmark discriminates.

[VISUAL: Final template: “Ready for [task], using [harness], if [acceptance threshold], with [human gates].” Below it, show separate outcome and operating-cost scorecards.]

**NARRATION:** For your team, define readiness as a tuple: task class, harness, acceptance test, and supervision regime. Predeclare thresholds. Track cost and latency separately from workflow activity, held-out correctness, review effort, escaped defects, and architecture. A claim survives only at the layer actually measured. If the evidence says “merged,” do not silently translate it to “correct,” “cheap,” or “safe.”
